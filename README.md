# UsageViewer

C# / .NET 10 Windows Forms로 만든 Codex·Claude 사용량 트레이 앱.
트레이 아이콘을 왼쪽 클릭하면 사용 한도 팝업이 열린다.

- 구간별 남은 비율·초기화 시각
- Codex·Claude·Gemini·Cursor·Copilot 설치 자동 감지 (실행 파일/PATH/설치 등록 정보)
- 사용량 연동은 Codex·Claude 지원. 나머지는 감지 여부와 미지원 상태만 표시
- ‘두 서비스 함께 보기’ 체크: 320 DIP 두 서비스 보기, 해제: 280 DIP 서비스 탭 보기
- 보기 방식과 마지막 선택 탭을 다음 실행에도 유지
- 서비스 탭·함께 보기 전환 중에는 상세창을 열린 채 유지
- 크레딧 잔액·무제한 상태 (서버에서 반환하지 않으면 미제공으로 표시)
- 클릭한 트레이가 있는 모니터 작업 영역의 오른쪽 아래 구석에 고정, 갱신 후에도 위치 유지
- Codex와 연결된 Claude 웹 페이지는 60초 갱신, Claude 수신 파일은 5초마다 확인. 상단 ↻로 수동 새로고침
- 사용량에 따른 트레이 색상, 마우스를 올리면 남은 비율 표시
- 조회 실패 시 이전 값 표시, 초기화 시각이 지나면 갱신 필요 표시
- 상단 264×32 DIP 요약 바 상시 표시, 클릭하면 바로 아래 상세 팝업
- 상단 Codex/Claude 영역을 누르면 해당 서비스 탭 상세를 바로 표시. 열린 상세창에서도 서비스 전환
- 잔여 10% 이하 붉은 강조·짧은 알림, 5% 이하 약 1.2초 사이렌. 같은 구간·단계에서는 한 번만 알림
- 로컬 자정까지의 추가 사용 권장량(%p)과 유지할 주간 잔여량(%)을 상세·함께 보기·상단 툴팁에 표시
- 탭/바를 드래그해 위쪽 위치와 모니터를 변경. 놓은 모니터 작업 영역 상단에 붙고 위치를 기억
- 오른쪽 클릭 메뉴의 ‘모니터 상단에 표시’·‘항상 가장 앞에 표시’ 체크 옵션
- 오른쪽 클릭 메뉴의 사용량 보기·새로고침·종료
- 바깥 클릭 / Escape / ×로 팝업 숨기기, 다시 실행하면 기존 팝업 열기

## 실행

Windows 10/11, .NET 10 Desktop Runtime, ChatGPT 계정에 로그인된 Codex CLI가 필요하다.
Claude 웹 연결에는 Microsoft Edge WebView2 Runtime이 필요하다.
개발 빌드에는 .NET 10 SDK가 필요하다.

```powershell
dotnet build .\src\UsageViewer\UsageViewer.csproj -c Release
.\src\UsageViewer\bin\Release\net10.0-windows\UsageViewer.exe
```

작업 표시줄의 숨겨진 아이콘 영역에 표시될 수 있다. 트레이의 아이콘을 눌러 팝업을 연다.
실행 직후 팝업을 열려면 `UsageViewer.exe --show`를 사용한다.
사용자 폴더에 SDK를 설치했다면 `& "$env:USERPROFILE\.dotnet\dotnet.exe"`로 실행할 수 있다.

Codex는 Desktop 번들 → PATH의 `codex.exe` → 기본 npm 설치 경로 순서로 찾는다.
직접 지정하려면 앱 실행 전에 환경 변수에 네이티브 실행 파일의 절대 경로를 넣는다.

```powershell
$env:USAGEVIEWER_CODEX_PATH = 'C:\path\to\codex.exe'
.\src\UsageViewer\bin\Release\net10.0-windows\UsageViewer.exe
```

`.cmd` / `.ps1` 실행기는 사용하지 않는다. 기존 CLI가 ChatGPT로 연결되어 있으면 그 로그인을 사용한다.
CLI가 API 키로 연결되어 있거나 다른 앱과 인증이 섞이면 팝업의 **ChatGPT 연결하기** 또는
트레이의 **Codex 구독 연결 / 계정 확인**을 누른다. 브라우저에서 Codex 앱과 같은 구독 계정으로 직접 로그인한다.
전용 연결 후에는 표시기 프로필의 로그인을 우선 사용한다. 다른 앱을 위해 전역 `codex login`을 바꿀 필요가 없다.

일반 새로고침과 `--diagnose`는 전용 프로필이 있으면 먼저 조회한다. 정상 전용 조회는 기본 CLI를 추가 호출하지 않는다.
전용 조회가 인증 갱신·401·연결/응답 오류 등으로 실패하면 그 프로세스를 종료한 뒤 기본 CLI로 한 번만 재조회한다.
전용 프로필이 없으면 처음부터 기본 CLI만 사용한다. 기본 CLI도 실패하거나 미로그인·API 키·잘못된 응답이면
오류를 표시하며 성공이나 0%로 처리하지 않는다. **ChatGPT 연결하기**의 명시적 로그인 실패·사용자 취소에는 재시도하지 않는다.

전용 연결은 `%LOCALAPPDATA%/UsageViewer/CodexProfile`에서 Codex 자체가 관리하며 인증 파일을 직접 읽거나 복사하지 않는다.
이 자식 프로세스만 전용 `CODEX_HOME`과 파일 자격 증명 저장소를 사용하고 API 키·워크로드 인증 환경 변수를 제외한다.
다른 프로세스의 환경, 기존 Codex 홈·계정·대화·설정은 변경하지 않는다.
기본 CLI 조회는 전용 연결 전과 fallback 모두 사용자 지정 `CODEX_HOME`과 상속받은 인증 환경을 그대로 따른다.
`USAGEVIEWER_CODEX_PATH`로 지정한 실행 파일도 두 시도에서 유지한다.

## 조회 방식과 범위

[OpenAI 공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)에 따라
`codex app-server --listen stdio://`를 실행하고 `initialize` / `initialized` 이후
평소에는 `account/read`, `account/rateLimits/read`만 호출한다.
사용자가 표시기 전용 연결을 선택한 경우에만 전용 프로필에서 `account/login/start`를 추가로 호출한다.
일반 조회 전체는 재시도를 포함해 30초 제한을 공유하며, 취소·제한시간 경과 후에는 재시도하지 않는다.
명시적 연결의 제한시간은 5분이다. 각 자식 프로세스는 정리 시 최대 1초의 정상 종료 대기 후 프로세스 트리와 함께 종료한다.

앱은 인증 파일·토큰을 직접 읽거나 저장하지 않는다. 전용 연결의 저장과 인증 갱신 등 내부 처리는 Codex CLI가 담당한다.
대화 생성, 모델 실행, 초기화 크레딧 사용, 계정 설정 변경은 하지 않는다.
사용량은 ChatGPT 계정의 할당량 비율이다. API 과금 내역이나 토큰 합계는 표시하지 않는다.
구간 길이는 계정 응답 기준이므로 주간 구간만 나오는 계정도 있다.
표시 시각은 Windows 시스템의 로컬 시간이다. 초기화 시각 경과만으로 남은 비율을 추정하지 않는다.
App Server 및 계정 응답은 Codex 버전에 따라 달라질 수 있다.

계정 식별 정보와 원본 응답은 로그로 남기지 않는다. Codex 조회 스냅샷은 메모리에만 보관한다.
재시작에도 오늘의 목표를 유지하기 위한 최소 일일 기준 상태는 별도 로컬 파일에 저장한다.
외부에서 접속할 수 있는 서버를 열지 않으며, 자동 시작을 등록하지 않는다.

읽기 전용 연동 진단은 팝업 없이 실행할 수 있다. 보고서에는 성공 여부·구간 수·길이·초기화 시각과
크레딧 정보/잔액 필드의 제공 여부를 남긴다. 잔액 값은 기록하지 않는다.

```powershell
Start-Process .\src\UsageViewer\bin\Release\net10.0-windows\UsageViewer.exe `
    -ArgumentList '--diagnose', '.artifacts\diagnostics.json' -Wait -WindowStyle Hidden
Get-Content .artifacts\diagnostics.json
```

전용 프로필 fallback의 재실행 가능한 회귀 검증은 Release 빌드 후 실행한다.
도구는 .NET 10 SDK(기본 `$env:USERPROFILE\.dotnet\dotnet.exe`, 필요하면 `-DotNetPath` 지정)와 PowerShell 7을 사용한다.

```powershell
pwsh -NoProfile -File .\Tools\Test-CodexProfileFallback.ps1
```

실제 Release DLL의 클라이언트를 별도 임시 프로필·가짜 네이티브 CLI로 호출하며 실제 로그인은 사용하지 않는다.
테스트 프로젝트·외부 패키지 없이 SDK 컴파일러로 프로토콜 fixture만 생성하고, Git 제외 `.artifacts`의 임시 파일은 종료 시 제거한다.
선택 순서·최대 1회 재시도·오류·명시적 연결·취소·전체 제한시간·자식 프로세스 종료·환경 격리를 확인한다.
구현 범위와 실행 결과, 실계정/화면 확인 여부는 [전용 프로필 fallback 계획](Docs/Plan/CodexProfileFallback.md)에 기록한다.
2026-11-07 검증: Release 빌드(경고·오류 0개), 실제 클라이언트 격리 회귀 37개, `git diff --check` 통과.
실계정 `--diagnose`는 현재 환경에서 API 키 연결 오류로 종료하여 ChatGPT 로그인 재사용 성공은 미확인이다.
실제 화면은 사용자 확인 대상이며 실행 중인 앱은 교체하지 않았다.

## Claude 앱 사용량 연결

1. 자동 감지된 Claude 영역의 **연결하기**를 누른다. 또는 트레이 오른쪽 메뉴의 **Claude 구독 연결 / 계정 확인**을 사용한다.
2. 열린 Claude 공식 페이지에서 데스크톱 앱과 같은 계정으로 직접 로그인한다.
3. 사용량 페이지에 한도가 표시되고 창 위쪽에 **사용량 수신 완료**가 나타나는지 확인한다.
4. 창을 닫으면 트레이에서 주기적으로 페이지를 다시 열어 갱신한다.

기존 Claude 앱의 인증 파일이나 브라우저 쿠키는 읽지 않는다. 연결 창은 별도 WebView2 프로필을 사용하므로
여기서 한 번 로그인해야 한다. 프로필은 `%LOCALAPPDATA%/UsageViewer/ClaudeWebProfile`에 WebView2가 관리한다.
로그인 입력과 인증 데이터는 앱의 사용량 캐시나 로그로 기록하지 않는다.

사용량 페이지가 실제로 받은 응답에서 5시간·주간 한도만 읽고
`%LOCALAPPDATA%/UsageViewer/claude-web-usage.json`에 정규화해 저장한다.
이 웹 응답은 공개 API 계약이 아니므로 페이지 형식이 바뀌거나 한도를 반환하지 않으면 오류를 표시한다.
실제 로그인·최초 웹 사용량 수신은 아직 검증하지 않았다. 빌드 및 예시 응답 파싱 검증과 구분한다.

## 팝업 디자인

실제 팝업은 앞서 선택한 시안과 같은 HTML/CSS 구조를 내장 WebView2로 표시한다.
함께 보기 너비는 320 DIP, 탭 보기 너비는 280 DIP이며 내용에 맞춰 높이를 조절한다.
체크박스 선택을 기억하고 트레이에서 열 때 작업 영역 오른쪽 아래 고정을 유지한다. 설치 감지는 인증 파일에 접근하지 않는다.
상단 바에서 열면 264 DIP 너비로 바 바로 아래에 연결되며, 접합부 모서리를 펴서 하나의 화면처럼 표시한다.

상단 표시를 켜면 264×32 DIP 요약 바가 계속 표시된다. 마우스가 떠나도 접히지 않는다.
바의 여백이나 본문을 누른 채 드래그해 좌우 위치를 바꿀 수 있다.
다른 모니터로 끌어 놓으면 그 모니터 작업 영역의 위쪽에 붙는다.
Codex 영역을 누르면 Codex, Claude 영역을 누르면 Claude 탭 상세가 열린다. 서비스 영역을 다시 눌러도 닫히지 않는다.
그립이나 오른쪽 화살표를 누르면 상세 팝업을 열고 닫는다. 서비스별 상세 선택 시 탭 보기와 선택 서비스를 기억한다.
상세 팝업을 닫아도 요약 바는 그대로 남는다.

트레이 또는 상단 바의 오른쪽 메뉴에서 ‘모니터 상단에 표시’와 ‘항상 가장 앞에 표시’를 각각 바꾼다.
항상 앞 옵션은 상단 바와 상세 팝업 모두에 적용된다. 옵션을 끄면 보통 창 순서로 표시된다.
상단 바는 외부 창 전환·최상위 상태 해제 시 활성화 없이 창 순서를 복구한다. 상세창·메뉴를 연 동안에는 보류한다.
선택 모니터의 테두리 없는 전체화면 창이 전경이면 상단 바를 자동으로 숨기고, 돌아오면 다시 표시한다.
일반 제목 표시줄·크기 조절 테두리가 있는 창은 전체화면 숨김 대상으로 보지 않는다.
드래그하는 동안 작업 창의 포커스를 유지하며, 상세 보기를 클릭할 때만 활성화한다.
보기 방식·선택 탭·상단 표시·항상 앞 옵션·모니터·가로 위치는 같은 `view.json`에 저장한다.

## 잔여량 경고

Codex·Claude의 유효한 5시간/주간 등 모든 한도를 확인한다. 잔여 10% 이하는 붉은 주의 표시와
약 6초 알림, 5% 이하는 긴급 알림과 짧은 ‘위이잉’ 사이렌을 한 번 제공한다. 상세창을 강제로 열거나 깜박이지 않는다.
다른 한도가 더 적으면 상단 바에도 그 구간을 우선 표시한다. 사용량을 모르면 경고하지 않는다.

같은 제공자·한도·초기화 구간에서 단계별로 한 번만 알리고, 주의에서 긴급으로 내려가면 추가로 한 번 알린다.
여러 구간의 동시 알림은 묶고 연속 알림은 최소 1분 간격을 둔다. 15% 이상 회복하거나 초기화 구간이 바뀌면 다시 알릴 수 있다.
조회 실패·만료·15분 이상 오래된 수신은 경고에서 제외하며 전체화면 작업 중에는 알림과 소리를 보류한다.

우클릭 메뉴의 **잔여량 경고음** 체크를 끄면 사이렌을 재생하지 않고 현재 소리도 중단한다.
기본은 켜짐이며 `view.json`에 기억한다. 소리는 외부 음원 없이 메모리에서 합성한다.
중복 방지용 `alerts.json`에는 구간 해시·알린 단계·시각만 저장한다. 사용량 수치·계정 ID·인증 정보는 포함하지 않는다.
이 파일을 지우면 중복 방지 기록도 초기화된다. 알림 기록을 저장할 수 없으면 해당 실행 중에만 중복을 막는다.

## 사용 여유 안내

수신된 한도 구성을 구분해 ‘5시간 · 주간’ 또는 ‘주간 · 5시간 미제공’으로 표시한다.
구독 이름이나 primary/secondary 위치 대신 실제 응답의 구간 길이를 사용한다.
‘5시간 미제공’은 응답에 해당 구간이 없다는 뜻이며, 한도 없음·무제한으로 판단하지 않는다.
구간 길이가 누락되면 ‘구간 정보 미제공’으로 표시한다.

실제 길이가 10080분인 주간 한도에 대해 ‘오늘 자정까지 추가 약 X%p 사용 권장’,
‘주간 잔여 Y% 이상 유지’를 함께 안내한다. 오늘의 끝은 Windows 시스템 로컬의 다음 자정이며,
주간 초기화가 먼저 오면 ‘초기화 전까지’로 표시한다. %p는 해당 모델의 주간 전체 한도 기준이다.
리셋 때 10%를 남기도록 남은 시간을 균등 배분한 참고 예산이며 실제 사용 가능량이나 질문·토큰·작업시간의 보장이 아니다.

당일 첫 유효 수신의 잔여량 R0, 시각 t0, 종료 E=min(다음 자정,reset)으로
`B0=max(0,R0-10)×(E-t0)/(reset-t0)`를 구한다. 목표 잔여량 `F=R0-B0`를 소수 둘째 자리로 올림해
고정하고, 이후 추가 권장량 `max(0,R현재-F)`는 소수 둘째 자리로 내림한다.
예를 들어 2026-11-09 16:10(+09:00)에 78%가 남고 11-14 01:10에 초기화된다면
추가 5.07%p·잔여 목표 72.93%이다. 잔여가 76%가 되면 추가 권장량은 3.07%p이다.
같은 날 반복 조회와 재시작은 목표를 다시 배정하지 않는다. 잔여량이 상향 정정되어도 같은 목표를 사용한다.

모델별 주간 예산은 각각 계산하고 가장 작은 추가 권장량을 요약에 모델/구간명과 함께 표시한다.
다른 모델도 같은 예산을 쓸 수 있다는 뜻은 아니다. 5시간 한도가 빠듯하면 별도 절약 안내를 유지하고,
잔여 10% 이하 경고를 우선한다. 주간 미제공은 일일 예산 계산 불가로 표시하면서 기존 단기 한도 안내를 유지한다.
상세·함께 보기·툴팁은 같은 결과를 공유하며 기존 5초 수신 확인 주기에 자정과 freshness도 반영한다. 추가 조회는 없다.

목표 도달·주간 잔여 10% 이하 등 정상 소진은 ‘오늘 추가 권장량 없음’으로 구분한다(낮은 잔여 경고는 우선).
조회 실패·미수신·15분 초과·미래/역행 시각·잘못된 값·만료·길이/reset 누락·한도 식별 모호함은 ‘계산 보류’이다.
일일 예산은 미래 수신을 1초라도 허용하지 않는다. 기존 잔여량 알림의 1분 미래 허용 규칙은 유지한다.
자정 이후에는 새 날짜의 수신이 필요하며 시간대 변경도 이전 수신보다 새로운 값이 필요하다.
날짜·시간대·reset·한도 구성 변경 시 새 기준으로 전환하고, 서머타임은 실제 경과시간으로 계산한다.

`%LOCALAPPDATA%/UsageViewer/daily-budget.json`에는 제공자, 해시 한도/구성/시간대 식별자,
날짜, 기준/최종 수신 시각, 종료/reset, 고정 목표만 보관한다. 이전 기준은 제공자별 다음 유효 평가 때 교체한다.
사용 이력·계정 정보·인증 정보·원본 응답은 저장하지 않는다. 손상/읽기 실패는 목표를 임의 재배정하지 않고 보류하며,
상태 파일을 복구한 뒤 재실행해야 한다. 저장 실패도 보류하고 같은 실행 중의 목표를 유지해 다음 유효 평가에서 저장을 재시도한다.
파일 삭제 후 재실행하면 이전 목표는 복원할 수 없다. 계정을 식별하지 않으므로 동일 한도 구성/reset의 계정 전환은 감지하지 않는다.

Release 빌드 후 합성 회귀 검증을 실행한다. Windows PowerShell 5.1과 PowerShell 7을 지원한다.

```powershell
powershell -NoProfile -File .\Tools\Test-DailyUsageBudget.ps1
```

실제 Release DLL과 임시 상태·보기 설정 경로만 사용해 계산·당일 차감·재시작·저장 실패/손상·날짜/시간대/DST·
다중 모델·오류·공유 UI 데이터와 264×32 DIP 크기를 검증한다. 실제 화면의 긴 문구·조작 수용 여부는 user_check 대상이다.
실계정 조회와 실행 중인 앱 조작은 하지 않는다. 정책과 실행 결과는 [사용 예산 계획](Docs/Plan/UsagePacing.md)을 참고한다.

## Claude Code 보조 연동

Claude Code의 [공식 statusLine](https://code.claude.com/docs/en/statusline) 입력을 받는
`UsageViewer.exe --claude-statusline` 수집 모드를 제공한다. 입력 중 5시간·주간 비율과 초기화 시각만
`%LOCALAPPDATA%/UsageViewer/claude-usage.json`에 저장한다. 원본 입력이나 인증 파일은 저장·조회하지 않는다.
사용량은 Claude 응답 이후에 제공되므로 Claude를 사용하지 않는 동안에는 마지막 수신 값이다.
15분 이상 지난 수신은 오래된 값으로 구분한다. 크레딧 잔액은 이 입력에서 제공되지 않는다.

빌드 후 아래 명령으로 Claude의 `statusLine`을 연결한다. PowerShell 7이 필요하다.
기존 statusLine이 있으면 덮어쓰지 않으며 다른 설정을 보존한다.

```powershell
pwsh -NoProfile -File .\Tools\Connect-ClaudeStatusLine.ps1
```

터미널 보조 연동은 Claude Code 터미널 세션의 다음 응답부터 사용량이 수신된다.
웹 연결에서 받은 캐시가 있으면 웹 데이터를 우선 사용한다.
연결 도구를 다시 실행하면 이 도구가 만든 기존 명령의 PowerShell 호환 문제도 교정한다.
데이터가 없거나 해당 계정이 사용량을 제공하지 않으면 대기 안내를 표시한다.
Claude의 상태 표시줄 설정이 수집 스크립트를 참조하므로 이 프로젝트를 옮기면 연결 명령을 다시 실행해야 한다.
해제하려면 Claude의 `settings.json`에서 이 프로젝트를 참조하는 `statusLine` 항목만 제거한다.
보기 설정은 `%LOCALAPPDATA%/UsageViewer/view.json`에 보관한다.
