# 상단 바가 뒤로 가거나 숨는 현상 보정

2026-11-03: 일반 브라우저 창을 전환할 때 상단 바가 사라진다는 사용자 화면 제보.
스크린샷만으로 창 순서 하락과 전체화면 오인을 구분할 수 없으므로 두 경로를 보정한다.

## 범위

- ‘항상 가장 앞에 표시’가 켜진 경우에만 네이티브 최상위 상태가 사라지거나 외부 전경 창이 바뀌면 복구한다.
  `SetWindowPos(HWND_TOPMOST)`에 이동·크기 변경·활성화·소유자 순서 변경 금지 옵션을 사용한다.
- 매 틱 창을 앞으로 올리지 않는다. 상태가 정상이고 같은 전경 창이면 순서를 변경하지 않는다.
- 상세창/우클릭 메뉴/앱 자체 창 앞에서는 복구를 보류한다. 옵션 끔·상단 숨김·전체화면 숨김을 존중한다.
- 전체화면 판정에는 DWM의 실제 프레임 경계를 우선 사용한다. 일반 제목 표시줄이나 크기 조절 테두리가
  있는 창은 숨김 대상으로 보지 않는다. 모니터 전체를 덮는 테두리 없는 창의 숨김은 유지한다.
- 외부 창을 활성화하거나 수정하지 않는다. 인증·조회·잔여량 판단은 변경하지 않는다.

## 검증

순수 경계/스타일 판정, 작업 소유 테스트 창의 네이티브 최상위 해제→복구, 옵션 끔·상세창 보류,
반복 호출·활성화 불변·크기/위치 불변 및 기존 팝업/탭 검증. Release 빌드와 diff 공백 검사.
실제 사용자 앱이나 마우스를 제어하지 않고 별도 테스트 설정·프로필을 사용한다.
실제 브라우저·다중 모니터 전환 증상 해결 여부는 사용자 환경에서의 확인과 구분한다.

근거: [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos),
[GetWindowRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect),
[DWM 프레임 경계](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute).

## 결과

- Release 빌드 경고·오류 0개 및 diff 공백 검사 통과.
- 순수 전체화면 판정·음수 모니터 좌표·작업 영역 최대화·프레임 유무·빈 경계,
  테스트 소유 창의 네이티브 최상위 강제 해제→복구·타이머 경로·정상 상태 반복 시 재배치 없음·
  숨김/옵션/상세창/자체 전경 보류·포커스/위치/크기 불변 등 30개 검증 통과.
- 격리 WebView2에서 기존 서비스 탭·두 보기·닫기/Escape·한도/여유 안내 등 52개 검증 통과.
- 투명 테스트 창만 조작했다. 사용자 브라우저·마우스·계정은 조작하지 않았다.
  실제 브라우저 전환 증상은 새 빌드에서 사용자 확인이 필요하다.
- 사용자 푸시 요청에 따라 이 보정과 관련 문서만 게시한다. 검증 산출물과 개인 설정은 포함하지 않는다.
