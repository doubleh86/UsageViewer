# Codex 전용 프로필 조회 실패 시 기본 CLI 재조회

작성일: 2026-11-07

## 원인과 목표

작업 요청에 첨부된 사전 읽기 전용 진단에서 기본 CLI의 ChatGPT 계정·한도 조회는 성공했지만 표시기 전용 프로필은
인증 갱신 실패와 HTTP 401을 반환했다. 기존 클라이언트는 전용 폴더의 존재만으로 그 프로필을
선택하므로 기본 CLI의 정상 로그인을 재사용할 수 없었다.

일반 조회는 정상 전용 프로필을 우선하고, 전용 조회가 실패하면 기본 CLI 컨텍스트로 한 번만
재조회한다. 실패 원문이나 인증 파일을 분석하지 않고 기존의 안전한 오류 경계를 사용한다.

## 범위와 구현 계획

- `src/UsageViewer/Services/CodexUsageClient.cs`: 조회 전체의 제한시간·취소와 개별 프로세스 수명을
  분리한다. 일반 조회의 전용 프로필 실패에만 기본 CLI 재시도를 허용한다.
- `src/UsageViewer/Models/UsageSnapshot.cs`: 필요한 경우에만 국소 예외 모델을 조정한다.
- `Tools/Test-CodexProfileFallback.ps1`: 빌드한 실제 클라이언트를 호출하고 별도 임시 프로필과
  가짜 네이티브 CLI 응답으로 회귀 검증한다. 구현을 복제하거나 테스트 프로젝트·패키지를 추가하지 않는다.
- `README.md`: 전용 → 기본 CLI 선택 순서, 재시도 한계, 검증 결과와 미확인 사항을 기록한다.
- 명시적 `ConnectAsync`의 로그인 실패·취소는 그대로 전파한다. 일반 조회에서 로그인 RPC를 호출하지 않는다.
- 기본 CLI는 상속받은 `CODEX_HOME`과 인증 환경을 유지한다. 실행 파일 지정과 전용 자식 환경 격리를 보존한다.
- 조회 전체에 기존 30초 제한(명시적 연결 5분)을 한 번만 적용한다. 각 시도의 stderr 배수·종료는
  독립적으로 정리하고, 취소·제한시간 경과 후 새 프로세스를 시작하지 않는다.
- 실패·미로그인·API 키·잘못된 응답은 오류로 유지하고, 개인정보·토큰·RPC/stderr 원문은 기록하지 않는다.
- 인증·계정·설정 파일, 다른 앱 환경과 실행 중인 사용자 앱은 수정하지 않는다. 커밋·배포는 수행하지 않는다.

## 검증 계획

1. 지정된 .NET 실행 파일로 `UsageViewer.csproj` Release 빌드.
2. 재실행 가능한 PowerShell 검증으로 정상 전용/프로필 없음/인증 갱신 실패/401/연결 종료와
   기본 CLI 최대 1회 재시도, 기본 CLI 실패·미로그인·API 키·잘못된 응답을 확인한다.
3. 실제 `ReadAsync`/`ConnectAsync` 호출에서 사용자 취소, 공유 제한시간, 두 프로세스 종료,
   사용자 지정 CLI·`CODEX_HOME`과 부모 환경 보존, 허용 RPC만 호출하는지 확인한다.
4. 가능하면 기존 `--diagnose`로 실제 기존 로그인 재사용을 읽기 전용 확인한다. 원본 응답은 기록하지 않는다.
5. 자기 diff와 `git diff --check`를 확인한다. 산출물은 Git 제외 임시 영역에만 둔다.
6. 실계정 조회 결과와 UI 화면 확인을 별도로 기록한다. 실제 화면은 사용자가 확인하며 앱을 자동 교체하지 않는다.

공식 계약: [Codex App Server](https://learn.chatgpt.com/docs/app-server)의 초기화와
`account/read` (`refreshToken: false`), `account/rateLimits/read`를 사용한다.

## 상태

- 구현 완료: 일반 조회만 안전한 `UsageQueryException` 실패에서 한 번 재시도한다.
  응답 필드 형식 오류(`InvalidOperationException`)도 원문을 포함하지 않는 조회 오류로 변환한다.
  기존 예외 모델로 충분하여 `UsageSnapshot.cs`는 변경하지 않았다.
- 각 프로세스의 stderr 취소를 전체 조회 취소와 분리했다. 첫 시도 정리가 두 번째 시도를 취소하지 않으며,
  정리 중 도착한 사용자 취소·제한시간도 다음 실행이나 성공 결과보다 우선한다.
- 최종 Release 빌드 통과: 경고·오류 0개. 초기 제한 환경의 NuGet 이름 해석 실패는 기존 패키지 복원 접근 후 해결했다.
- 실제 로그인 재사용: 현재 실행 환경에서 기존 `--diagnose`를 읽기 전용 실행했다.
  제한 환경에서는 CLI 연결 종료로 실패했고, 접근 제한을 해제한 진단에서는 기본 CLI를 API 키 연결로 판정하여
  오류로 종료했다(exit 1). 사전 진단과 실행 컨텍스트가 같다는 근거가 없으므로 실제 ChatGPT 로그인 재사용
  성공으로 기록하지 않는다. 인증·계정·환경 설정을 바꾸어 우회하지 않았다.
- 실제 화면: 미확인. 사용자 확인 대상이며 실행 중인 사용자 앱을 교체하거나 UI를 자동 조작하지 않았다.
- `pwsh -NoProfile -File Tools/Test-CodexProfileFallback.ps1` 최종 통과: 실제 Release DLL을 호출한 37개 시나리오.
  정상 전용 우선·프로필 없음·인증 갱신/401 fallback·연결/응답 오류·강제 종료 13개,
  기본 CLI 오류 12개, 명시적 연결 6개, 나머지 취소 경계 4개, 제한시간 경계 2개를 확인했다.
- 제한시간 검증: 전용 조회가 30초를 소진하면 재시도 0회. 전용 조회가 20초 후 실패하고 기본 CLI가
  응답하지 않으면 처음부터 공유한 30초 제한으로 종료한다. 프로세스 정리를 포함해 36초 미만임을 확인했다.
- 두 프로세스가 EOF 후에도 종료하지 않는 응답에서 강제 종료를 확인했고, 기본 CLI 시작 시 첫 프로세스가
  이미 종료됐는지와 각 호출 완료 후 프로세스가 남지 않는지를 확인했다.
- 사용자 지정 `CODEX_HOME`/미설정 상태·CLI 경로·부모 환경 보존, 전용 자식의 인증 환경 제외,
  일반 조회의 로그인/모델/대화 RPC 부재, stderr 배수와 실패 원문 비노출을 확인했다.
- 자기 diff와 `git diff --check` 통과. 신규 파일의 끝 공백·탭도 확인했다.
  검증 fixture는 실행별 Git 제외 임시 영역에 생성 후 제거했고, 진단 보고서는 Git 제외 영역에만 남겼다.
