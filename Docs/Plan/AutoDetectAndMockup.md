# 설치 자동 감지와 승인 시안 일치

## 요청

설치된 AI를 자동으로 찾아 표시하고, 실제 팝업을 앞서 제공한 ‘한눈에’/‘탭으로 전환’ 시안과 일치시킨다.
두 보기 전환 체크박스와 오른쪽 아래 고정은 유지한다. Computer Use는 하지 않는다.

## 구현 범위

- Codex·Claude·Gemini·Cursor·Copilot의 알려진 실행 파일·설치 등록 정보를 감지한다. 인증 파일과 토큰은 읽지 않는다.
- Codex는 설치된 CLI로 자동 조회, Claude는 이미 연결한 앱 전용 웹 프로필이나 수신 캐시를 자동 재사용한다.
- Claude 데스크톱 설치만으로 기존 로그인 정보에 접근하지 않는다. 연결이 필요한 경우 해당 서비스 안에 작은 연결 동작을 표시한다.
- Gemini·Cursor·Copilot은 감지와 사용량 연동을 구분해 ‘감지됨 · 사용량 연동 미지원’으로 표시한다. 임의 비율은 만들지 않는다.
- 팝업 본문에 WebView2를 사용해 승인 시안의 HTML/CSS 구조·크기·서체·구분선·아이콘·여백을 실제 앱에 적용한다.
- 상단의 추가 연결 버튼을 제거한다. 연결 안내는 해당 서비스 내용 안에 배치한다.
- 영향 파일: 설치 감지 서비스, UsagePopup 및 포함 HTML, TrayApplicationContext, 보기 설정 검증, 프로젝트 리소스, README.

## 검증

Release 빌드, 알려진 설치 경로/등록명 감지, 지원/미지원 구분, 로컬 HTML의 실제 렌더링과 두 보기 크기·체크박스 전환 검증.
예시 데이터 화면은 실계정 조회 성공과 구분한다. 실제 Claude 로그인·웹 수신의 기존 미확인 상태는 유지한다.

## 결과

- 이 PC의 Codex·Claude 설치를 실제 감지했다. 별도 실행 파일 예시로 Gemini·Cursor·Copilot 감지 및 사용량 미지원 분류를 확인했다. 해당 실행 파일을 실행하지 않았다.
- 실제 Windows 팝업 호스트의 내장 문서 렌더링을 별도 프로필과 예시 데이터로 검증했다. 함께 보기 320×336, 탭 보기 280×246 CSS 픽셀, 본문 13px, 탭 주 수치 24px, 가로 잘림 없음.
- 실제 HTML 체크박스 → C# 메시지 → 설정 파일 저장 경로를 확인했다. 시안 기준으로 서체·여백·구분선·작은 로고·아이콘·둥근 모서리를 확인했다.
- 렌더링 검증은 화면 밖의 투명 테스트 창으로 수행했다. 사용자 앱과 로그인 화면을 조작하거나 Computer Use를 호출하지 않았다.
- 최초 문서 내부 탐색을 일률 차단하던 문제를 실제 렌더러 검사로 발견하여 교정했다. 문서 로드 이후 외부 탐색 차단과 네트워크 없는 CSP를 적용했다.
- 최종 Release publish 성공. `UsageViewer-v0.1.0-win-x64-autodetect-ui-20261030-124341.zip`을 바탕화면에 복사하고 SHA-256 일치를 확인했다. 이 작업의 이전 버전을 새 앱으로 교체했다.
- 기존 사용자·다른 작업자의 규약/README/ignore 변경은 보존했다. 커밋·push는 하지 않았다.
