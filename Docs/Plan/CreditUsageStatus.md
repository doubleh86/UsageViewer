# 크레딧 잔액과 차감 확인 표시

2026-11-24 · 구현 및 로컬 배포 요청

## 목표와 상태

- 구독 한도가 소진돼도 크레딧으로 이용하는 사용자가 ‘초기화를 기다려 주세요’만 보지 않게 한다.
- 신선한 조회에서 잔액이 있으면 ‘크레딧 잔액 보유’, 같은 계정의 연속 조회에서 잔액 감소를 확인하면
  파란색 ‘크레딧 차감 확인’과 직전 정상 잔액 대비 감소량을 표시한다.
- 이는 계정 잔액 감소의 관찰이며 현재 앱/대화의 과금 경로나 실시간 사용 중 상태를 단정하지 않는다.
  공식 `CreditsSnapshot`은 `balance`, `hasCredits`, `unlimited`를 제공하며 사용 중 플래그는 없다.
  근거: [공식 프로토콜](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/account.rs).

## 판정 규칙

- 기존 계정/한도 읽기 RPC만 이용한다. 응답의 `accountId`가 있으면 메모리 내 해시로 비교 계정을 구분한다.
  인증 파일을 직접 읽지 않고 식별 원문·해시·잔액 이력을 파일이나 팝업 JSON에 저장하지 않는다.
- 계정 식별 정보가 없는 응답은 현재 잔액만 표시하며 서로 같은 계정이라고 가정해 감소를 판정하지 않는다.
- 계정·한도 구간 ID 변경, 조회 실패, 15분 초과 공백, 잔액 미제공/무제한, 잘못된 비율·수신 시각은 비교를 초기화한다.
  첫 조회에서 사용 중으로 표시하지 않으며 재실행 후에도 새 비교를 시작한다.
- 같은 수신을 여러 번 렌더해도 다시 차감하지 않는다. 역순 수신으로 새 정상 상태를 덮어쓰지 않는다.
- 잔액 감소를 확인하면 해당 감소량을 최근 15분 동안 표시한다. 그대로면 유지하고 증가하면 해제한다.
  0.01 미만 감소도 0으로 표시하지 않는다. 잔액 0은 ‘크레딧 잔액 없음’으로 표시한다.
- 소진된 구독 구간과 유효한 크레딧 잔액이 함께 있으면 해당 구간을 ‘주간 한도 소진 · 크레딧 잔액 보유’로 안내한다.
  다른 모델/구간에 크레딧 정보를 임의로 적용하지 않고, 잔액 미제공·없음·오래됨에는 기존 소진 안내를 유지한다.
- 해당 소진 구간의 상세 경고는 크레딧 안내와 구분한다. 다른 구간 경고와 기존 상단 바·경고음 정책은 유지한다.
- Codex/Claude, 파란 오늘 시작선/흰 권장선, 미니 덱, 오늘/내일 배분 공식과 사용자 설정은 보존한다.

## 범위와 검증

- 모델/파서의 메모리 전용 계정 범위, 크레딧 비교 서비스, UsagePopup/HTML, 기존 합성 검증과 README.
- 첫 조회/감소/동일/증가/0/미제공/무제한/계정·구간 변경/식별 없음/중복/역순/오류·오래됨을 검증한다.
- 실제 배포 DLL과 격리 WebView2에서 264/280/320 DIP 및 두 보기의 문구·색상·작은 감소량·경고 분리를 확인한다.
- Release 빌드·ZIP의 라이선스/개인 파일 제외/해시 확인 후 바탕화면에 새 폴더와 ZIP을 복사한다.
  확인된 이전 UsageViewer 배포만 백업 후 정리하고 새 실행 경로와 DLL 해시를 확인한다.
- 사용자 요청은 구현·검증·바탕화면 배포·실행·이전 배포 정리까지이며 Git 커밋/push는 포함하지 않는다.

## 검증 결과

- 구현 완료: 계정 범위 해시와 비교 이력은 메모리에만 유지하고 화면에는 상태와 직전 감소량만 전달한다.
- 소스/HTML 검사 102개, .NET 10 Release publish와 실제 배포 DLL 합성 검증 876개 통과.
  격리 WebView2에서 264/280/320 DIP의 파란 표시·감소량·소진 안내와 기존 덱/Claude 갱신을 확인했다.
- 실제 크레딧을 소비하는 요청을 만들거나 결제/사용 설정을 변경하지 않았다.
- 바탕화면 새 폴더/ZIP의 해시와 새 실행 경로를 확인했고, 확인된 이전 배포 폴더와 ZIP은 백업 후 삭제했다.
  실제 과금 경로나 차감 속도를 합성 검사로 단정하지 않는다. 커밋/push와 사용자 계정·설정 변경은 하지 않았다.
