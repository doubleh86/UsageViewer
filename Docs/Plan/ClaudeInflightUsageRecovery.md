# Claude 진행 중 사용량 요청 복구

## 목표와 범위

- 숨겨진 자동·수동 갱신에서 검증된 `/settings/usage`의 공식 GET이 먼저 등록되고, 같은 최상위 문서가 `/new`로 이동한 뒤에 응답하는 경우를 기존 30초 안에 처리한다.
- 전환 당시에 등록된 요청만 사용한다. 다른 문서·프레임·출처·쿼리, 새 요청, 캐시 응답과 사용자 연결 창에는 예외를 적용하지 않는다. 상태 분류와 저장 조건은 유지한다.
- 변경 범위: `ClaudeConnectionWindow.cs`, `Tools/Test-ClaudeRefreshReliability.ps1`, `Tools/Test-UsagePacing.ps1`, 이 문서 및 `README.md`.

## 구현 및 검증 결과 (2026-11-19)

- 같은 최상위 프레임과 로더로 이미 확인된 시도에서 `/new` 전환 시 등록된 후보를 고정한다. 전환 이후에도 상태·본문·저장 검증과 기존 마감 시각을 적용한다.
- 외부 통신을 차단한 임시 프로필의 실제 WebView2에서 공식 GET → 같은 문서 `/new` → 지연된 200을 재현했다. 변경 전 DLL은 `NavigationFailed`였고 캐시가 그대로였다. 변경 후에는 숨겨진 자동·수동 각각에서 `/new`에서 발행한 별도 200을 무시하고, 원래 값으로 정규화 캐시를 한 번 교체해 `Success`가 됐다.
- 적격 후보 없음, 하위 프레임, 다른 로더·문서·출처, 임의 경로·쿼리, 시간 초과, 표시·닫기·종료, 로그인·접근 차단·서버 대기·비정상 본문을 확인했다. 캐시·서비스워커 표시와 불일치 응답 식별자는 지연 요청에 합성 CDP 응답 메타데이터를 주입해 검사했다. 기존 `/settings` 경유와 재시도, Codex 독립 갱신 검사도 통과했다.
- PowerShell 7 소스/HTML 35건, Release 단일 프로젝트 빌드(.NET SDK 10.0.403), 해당 DLL 합성 검사 401건(격리 탐색과 팝업 렌더링 포함)을 통과했다. 이 작업에서는 실계정 재조회, 제품 설치, 실제 사용자 UI 전체 검증을 수행하지 않았다. 작업의 근거가 된 별도 실계정 후보 진단은 메모리 결과만 확인했으며 제품 설치·캐시 교체 검증이 아니다.
