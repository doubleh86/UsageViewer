# 작은 팝업과 Claude 지원

작성일: 2026-10-30

## 요청과 이번 범위

- 큰 카드 중심 팝업을 축소하고 Claude 사용량도 추가한다. 사용자에게 UI 시안을 먼저 제공한다.
- 이번에는 작은 팝업 시안과 Claude 데이터 수집·읽기 코드를 준비한다.
- 시안 선택 후 선택한 레이아웃에 Codex/Claude를 연결하고 실행 중인 앱에 적용한다.
- Computer Use와 사용자 인증 정보 접근은 하지 않는다.

## Claude 연동 근거

https://code.claude.com/docs/en/statusline 의 공식 `rate_limits.five_hour`, `seven_day`를 사용한다.
각 구간은 `used_percentage`, `resets_at`을 제공한다. 세션 첫 API 응답 이후 제공되며 구간이 없을 수 있다.
Claude가 동작할 때 전달하는 사용량 스냅샷이다. 독립적인 60초 서버 조회로 표현하지 않는다.
Claude 크레딧 잔액은 이 인터페이스에서 확인되지 않았으므로 미제공으로 처리한다.

## 구현

- `--claude-statusline`: stdin JSON에서 허용한 사용량 필드만 파싱하여 로컬 파일에 원자적으로 저장하고 짧은 상태 문구를 출력한다.
- 원본 stdin에는 대화 경로·세션 정보가 있으므로 원본을 기록하지 않는다.
- `ClaudeUsageStore`: 수집 파일을 읽고 누락·오류·오래된 데이터를 구분한다.
- 현재 Claude 설정에 statusLine이 없음을 확인했다. 이 차수에는 사용자 설정을 변경하지 않는다.
- 시안 적용 차수에서 statusLine 연결을 추가하며, 그때 기존 설정 유무를 다시 확인하여 보존한다.
- 영향 파일: Claude 사용량 모델·수집/읽기 서비스, Program, README, 본 계획.

## 검증

최소 Release 빌드. 예시 입력으로 5시간/주간·부분 누락·잘못된 비율·원본 개인정보 제거·조회 시각 보존 확인.
실제 Claude 첫 응답에 의한 데이터 수집과 새 UI 통합은 시안 선택 후 검증한다.

## 결과

- 완료: ‘한눈에’와 ‘탭으로 전환’ 두 가지 작은 팝업 시안, 너비·여백 조정 및 서비스 전환 예시.
- 완료: Claude statusLine 수집/읽기 코드 및 CLI 수집 진입점. Release 빌드 경고·오류 0개.
- 완료: 5시간/주간 비율, 한 구간 누락, 개인정보 필터링, 수신 시각 보존, 잘못된 비율 거절 검증.
- 미완료: 사용자 시안 선택, Claude 설정 연결, 실행 앱의 Claude 실제 수신과 통합 UI 적용.
- 현재 실행 중인 앱과 사용자 Claude 설정은 변경하지 않았다. 커밋·push는 하지 않았다.

## 두 보기 방식 적용

- 사용자 선택: 두 시안을 모두 제공하고 ‘두 서비스 함께 보기’ 체크박스로 전환한다.
- 체크 시 320 DIP 두 서비스 보기, 해제 시 280 DIP 서비스 탭 보기. 설정을 로컬에 보관한다.
- Claude 캐시는 5초마다 확인하고 Codex 서버 조회는 기존 60초 주기를 유지한다. 각 서비스의 실패와 수신 시각은 독립 표시한다.
- 큰 카드와 로고 대신 작은 사용량 행·짧은 크레딧 행을 사용한다. 오른쪽 아래 고정을 유지한다.
- 기존 Claude statusLine을 재확인하여 비어 있으면 수집 스크립트를 연결한다. 기존 값이 생겼다면 덮어쓰지 않는다.
- 영향 파일: UsagePopup, TrayApplicationContext, 작은 사용량 표시 컨트롤, 보기 설정 저장 서비스, Claude statusLine 연결 스크립트, README.
- 검증: 최소 빌드, 보이지 않는 폼의 두 모드 크기·체크/탭 전환·설정 보존, 서비스별 실패 분리, 수집 스크립트의 원본 정보 제거. 모델 호출과 Computer Use 없음.

### 적용 결과

- 구현 완료: 두 보기 전환·설정 저장·서비스별 독립 상태·Claude 수신 파일 연결.
- 폼을 띄우지 않는 검증 통과: 320/280 DIP 너비, 체크·탭 전환, 재로드 시 설정 유지, 각 서비스 실패 시 다른 서비스 표시 유지, 내용 폭.
- 수집 브리지 실행 검증 통과: 실제 자식 프로세스 stdin/캐시/stdout 연결, 원본 세션 정보 제거. 테스트 캐시는 `.artifacts/`에만 기록했다.
- 설정 연결 검증 통과: 다른 필드 보존, 재실행 무변경, 기존 statusLine 덮어쓰기 거절. 현재 사용자의 비어 있던 statusLine에만 연결을 추가했다.
- Release 빌드 경고·오류 0개. 실제 Claude 응답에 의한 최초 수신은 아직 미확인이다. 모델 호출은 하지 않았다.
- Computer Use와 인증 파일 조회, 커밋·push는 하지 않았다.

## Release ZIP 전달

- 사용자 요청: Release 빌드와 ZIP 압축 후 바탕화면 복사.
- .NET 10 Desktop Runtime을 사용하는 Windows x64 패키지에 앱·Claude 도구·실행 안내를 포함한다.
- Claude 수집기는 ZIP을 푼 폴더의 실행 파일을 먼저 찾고, 개발 체크아웃에서는 기존 경로를 사용한다.
- 빌드·진단·개인 설정·인증·캐시 원본은 패키지에 포함하지 않는다. 현재 실행 중인 앱은 종료하지 않는다.
- 검증: Release publish, ZIP 목록 및 압축 해제한 도구의 예시 입력 처리, 바탕화면 복사 후 SHA-256 일치.
- 완료: Release publish 성공, 예상 7개 파일만 포함됨을 확인. 압축 해제한 Claude 도구의 stdin 처리 검증 통과. `UsageViewer-v0.1.0-win-x64-Release-20261030-115920.zip` 바탕화면 복사 및 SHA-256 일치 확인.

## Claude 수신 실패 후속

- 사용자 환경: Claude Code 터미널과 Claude 데스크톱 사용. statusLine 방식은 터미널 수신에 의존하며 데스크톱 자체를 조회하지 않는다.
- 확인: 기존 연결 명령의 따옴표로 감싼 실행 파일 경로는 PowerShell에서 UnexpectedToken 구문 오류가 발생한다.
- 수정: 양쪽 셸에서 호출 가능한 명령을 생성하고 기존 UsageViewer 연결만 안전하게 갱신한다. 타 statusLine은 보존한다.
- 검증: Claude가 사용하는 셸을 거치는 stdin 입력·캐시·stdout 경로를 Git Bash와 PowerShell에서 확인한다. 실제 터미널 사용량 수신과 예시 입력 통과는 구분한다.
- 수정 ZIP을 새 파일명으로 바탕화면에 제공한다. 인증 정보·대화 내용·모델 실행·Computer Use는 사용하지 않는다.

## Claude 데스크톱 사용자 연결

- 정정: 사용자는 현재 Claude 데스크톱 앱을 사용한다. 터미널 statusLine만으로는 새 사용량이 들어오지 않는다. 셸 교정은 이 요구를 충족하지 못한다.
- UsageViewer의 ‘Claude 연결’에서 공식 `https://claude.ai/settings/usage` 페이지에 사용자가 직접 로그인한다.
- Microsoft WebView2의 별도 앱 프로필을 사용한다. 기존 Claude 앱·브라우저의 인증 파일/쿠키를 읽거나 복사하지 않는다.
- 공식 사용량 페이지가 실제로 받은 `/api/organizations/.../usage` 응답만 관찰한다. 대화 생성·모델 호출·로그인 자동화는 하지 않는다.
- 웹 응답은 문서화된 공개 API 계약이 아니므로 예상 필드가 없으면 오류를 표시하고 실제 값으로 가장하지 않는다. 실제 로그인 후 수신 전에는 연동 성공으로 보고하지 않는다.
- 웹 데이터 파서·로그인 창·별도 정규화 캐시·상단 연결 버튼·주기 갱신을 추가한다. WebView2 NuGet 및 Edge WebView2 Runtime이 필요하다.
- 검증: Release 빌드, 예시 사용량 응답 파싱과 불완전 응답 거절, UI 연결 이벤트, 패키지 의존성 확인. 실제 로그인·최초 웹 수신은 사용자가 수행해야 하므로 별도 미확인 상태로 남긴다.
- 구현: ‘Claude 연결’ 창과 웹 응답 관찰, 별도 정규화 캐시, 숨김 상태의 주기 갱신 및 사용자 프로필 재사용을 추가했다. 터미널 데이터는 보조 fallback으로만 유지한다.
- 검증 완료: Release 빌드 경고·오류 0개, 예시 5시간·주간 비율/초기화 시각 파싱과 3개 잘못된 응답 거절, 두 팝업 모드의 연결 버튼 영역, WebView2 Runtime 156.0.4314.50 존재, 패키지 필수 관리/네이티브 DLL 포함.
- 배포 파일: `UsageViewer-v0.1.0-win-x64-Release-claude-web-20261030-122003.zip` 바탕화면 복사 및 SHA-256 일치 확인. 이 작업의 이전 앱을 종료하고 웹 연결 버전을 트레이에 실행했다.
- 미확인: 실제 Claude 로그인 가능 여부 및 사용량 페이지의 최초 실응답 수신. 이 결과는 사용자 로그인 후 확인해야 하며, 예시 응답 검증을 실제 계정 연동 성공으로 간주하지 않는다.
