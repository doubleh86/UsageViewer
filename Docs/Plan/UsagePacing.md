## 판단 기준

- 실제 사용 속도 예측이 아닌, 각 한도를 전체 구간에 균등 배분한 참고 안내이다.
- 한도별 시간 잔여 비율은 `(리셋 시각 - 현재) / 전체 구간 길이 × 100`이다.
- 기준 잔여 비율은 시간 잔여 비율과 10% 중 큰 값이다. 안내를 위해 최소 10%를 남겨 둔다.
- 모든 한도를 평가하고 `남은 비율 - 기준 잔여 비율`이 가장 작은 한도를 판단 근거로 삼는다.
  여유가 10%p 이상이면 ‘사용량을 더 써도 됩니다!’, 0%p 이상이면 ‘리셋까지 사용 여유가 있어요’,
  0%p 미만이면 ‘리셋까지 조금 아껴 쓰세요’이다. 어떤 한도든 잔여 10% 이하는 낮은 잔여량 안내를 우선한다.
- 조회 실패·미수신·15분 초과·1분 초과 미래 수신·잘못된 비율·만료 구간은 긍정 안내를 표시하지 않는다.
  리셋 시각이나 구간 길이가 없거나 리셋이 전체 구간보다 멀면 판단 보류로 표시한다.
- 5시간이 넉넉해도 주간 한도가 부족하면 주간 한도를 기준으로 안내한다. 모든 모델별 한도를 함께 평가한다.
- 표시에는 판단 기준 한도의 남은 비율과 리셋 시간, ‘리셋 시간과 잔여량 기준’ 설명을 포함한다.
  상세의 보조 한도도 리셋 시간을 바로 표시한다.

구독 이름으로 한도를 추측하지 않고 응답의 실제 구간 길이를 사용한다.

- 상세·함께 보기·상단 툴팁에 ‘수신 한도 · 5시간 · 주간’, ‘수신 한도 · 주간 · 5시간 미제공’ 등 표시.
- ‘미제공’은 해당 응답에 구간이 없다는 의미이며, 구독 자체에 한도가 없거나 무제한이라는 뜻이 아니다.
- 5시간을 primary, 주간을 secondary로 가정하지 않는다. 실제 길이 순으로 표시해 5시간이 있으면 먼저,
  주간만 있으면 주간을 대표 값으로 표시한다. 낮은 잔여량의 상단 우선 표시는 유지한다.
- 길이 없는 구간은 ‘구간 정보 미제공’으로 표시하고 5시간 유무를 단정하지 않는다.
- 사용 여유 안내는 수신된 구간만 평가한다. 5시간 구간이 없어도 주간 구간으로 정상 평가한다.
- Codex·Claude 주간 단독, 5시간+주간, primary/secondary 역전, 기타/미상 구간과 실제 HTML·툴팁을 검증한다.
  조회·인증은 변경하지 않고 예시 데이터만 사용한다.

검증 결과: Release 빌드 경고·오류 0개. 기존 안내 정책을 포함해 56개 검증 통과.
Codex의 primary/secondary 각각에 주간만 있는 응답, Claude의 `five_hour: null`/주간 응답,
미상 구간·5시간 단독·중복 모델 구간·상단 대표 값과 툴팁 구분을 확인했다.
실제 HTML에서 Codex·Claude의 주간 단독·5시간+주간·역전/모델별 구간 순서·함께 보기·미상 구간,
기존 보기/탭/오류/닫기 동작 등 52개 검증 통과. 264 DIP 가로 잘림 없음과 실제 렌더링을 확인했다.
실제 계정 조회나 사용자 앱 조작은 하지 않았다.

## 게시 준비

2026-11-03 푸시 요청에 따라 소스·이력·배포 ZIP을 점검했다.
ZIP의 DLL에 이전 빌드에서 남은 PDB 절대 경로를 발견해 Release 설정에서 디버그 정보를 제외하고,
새 중간 출력 폴더에서 다시 빌드·패키징했다. 소스와 프로그램의 한도 판단 동작은 유지했다.
교체 패키지에서 해당 빌드 경로가 검출되지 않았으며 인증·개인 설정·로그·PDB를 포함하지 않는다.
MIT·WebView2 고지는 유지했다. 소스·이력·ZIP의 비밀정보/개인 경로 패턴 점검을 통과했다.
